# LLMReviewer

Large language models (LLMs) have shown strong potential for automating code review, yet their practical utility depends heavily on the design of generation and context strategies. In this paper, we investigate how to improve LLM-based code review through generation strategy and contextual augmentation. We first propose an *issue-list review* paradigm, in which LLMs enumerate all potential issues rather than reporting only the single most important one (i.e., *primary-issue review*). We then systematically compare three types of code context augmentation: neighboring, LSP-based semantics, and IR-based similar co-change context, and study how they influence issue discovery. Finally, we integrate candidates from no-context and context-enhanced generation to improve review coverage, and introduce refinement-guided pruning to keep the candidate list at a practical size. We evaluate our approach on 1,438 Go review instances and use downstream code refinement as the main effectiveness metric, i.e., how often the generated candidate list contains at least one comment that induces the same code change as the final human revision. For comparison, we also evaluate comments generated by CodeReviewer, a model trained specifically for review comment generation, as well as ground-truth human review comments (which serve as a practical upper bound), under the same refinement-based evaluation. The results show that our best configuration, combining issue-list review, neighboring and similar co-change context, and candidate integration, reaches 28.00% refinement exact match, a statistically significant overall gain of +10.85 percentage points over primary-issue review without any additional context (17.15%), substantially outperforming CodeReviewer (15.02%) and moving closer to the human-oracle ceiling of 36.09%. Our refinement-guided pruning strategy then reduces the average candidate count from 7.2 to 3.1 at top-5 while retaining nearly the full benefit, making the candidate list easier to inspect.

This package contains the LLM-based review-comment generation side of the project: prompt construction, context retrieval, context-augmented generation, candidate integration, and reranking. The companion CodeReviewer-based refinement package contains the downstream code-refinement and metric-computation pipeline used to evaluate generated review comments.

## Package Structure

- `llm_review_comment_generation/`: Main LLM review-comment generation pipeline.
- `llm_review_comment_generation/v3_list_reviewer.py`: Main entry for generating single-output and list-output review comments. The experiment settings are configured in the `if __name__ == "__main__"` block.
- `llm_review_comment_generation/prompt_builders/`: Prompt templates and shared prompt-building logic for primary-issue review (`single_p1`) and issue-list review (`list_p1` to `list_p4`).
- `llm_review_comment_generation/output(publish)/`: Published generated review-comment outputs used by the experiments.
- `llm_review_comment_generation/reranking/`: Candidate reranking and refinement-guided pruning utilities.
- `code_context_mangers/`: Code-context generation and rendering pipeline. It builds neighboring context, LSP-based semantic context, IR-based similar co-change context, random baselines, and combined context variants.
- `code_context_mangers/_context/`: Published context CSV files consumed by the generation pipeline.
- `code_context_mangers/_context_cache/`: Cached context data used to reproduce published context generation.
- `code_analysis_lsp/`: LSP-based code analysis layer used by semantic and similar-context generation.
- `llm_caller/`: Model provider wrappers and retry utilities.
- `_extended_data/`: Review-task input data used by the published generation pipeline.

## Companion CodeReviewer Package

The companion [CodeReviewerForLLM](https://github.com/brinnarlyne8585/CodeReviewerForLLM) package contains the refinement-based evaluation side:

- `use_as_metric/generation_pipeline/`: Converts generated comments into CodeReviewer refinement inputs and runs refinement inference.
- `use_as_metric/evaluation_pipeline/`: Computes refinement-based metrics for single-comment, list-comment, and reranked-list outputs.
- `use_as_metric/source(publish)/`: Published review-comment sources used for refinement evaluation.
- `use_as_metric/output(publish)/`: Published refinement outputs.
- `use_as_metric/rerank_index(publish)/`: Published reranked candidate indexes.
- `evaluation_results/`: Spreadsheet results reported in the paper.

Before using the CodeReviewer refinement package, configure `use_as_metric/paths.py` in that package.

## Reproducing Published Generation

The main generation entry is:

```bash
python3 llm_review_comment_generation/v3_list_reviewer.py
```

The key experiment settings are grouped near the bottom of that file:

```python
llm_model = "tencent-v3"
PROMPT_VERSION = "list_p2"
EXPERIMENTS = [
    ("neighborhood_similar", "26A-similar-medium-0.001", True),
]
RUN_IDS = [4]
```

Each experiment tuple is:

```python
(context_mode, context_version, use_file_content_flag)
```

The corresponding context file is loaded from `code_context_mangers/_context/` using the pattern:

```text
1438_go_from_ref-test_with_{context_mode}({context_version}).csv
```

## Context Generation

Context files can be regenerated through `code_context_mangers/run_for_code_context.py`. For reproducing the published experiments, keep cache-based LSP querying enabled and use the bundled `code_analysis_lsp/lsp_query_cache.db`. For new data or live LSP queries, configure `code_analysis_lsp/lsp_config.py` and start:

```bash
python3 -m code_analysis_lsp.lsp_manager.lsp_server_manager
```

See `code_context_mangers/README.md` and `code_analysis_lsp/README.md` for module-level details.

## Configuration Notes

- Configure model providers under `llm_caller/` before running new LLM generations.
- Configure repository paths and language-server tools in `code_analysis_lsp/lsp_config.py` before generating new semantic or similar context.
- The published CSV outputs are included for analysis and reproduction. They should not be translated or normalized as source code because they contain original review data, code snippets, and generated model outputs.
